# DTC static cross-builds

> Disclaimer: Everything (updates/modifications) in this project was generated by AI. Please review and test thoroughly before using in production.

Builds statically linked, stripped binaries of the
[Device Tree Compiler](https://git.kernel.org/pub/scm/utils/dtc/dtc.git)
(`dtc`, `fdtget`, `fdtput`, `fdtdump`, `fdtoverlay`) with YAML output
support, for Linux and Windows, using `zig cc` inside Docker.

| OS      | x86 | x64 | arm | aarch64 | riscv64 |
|---------|:---:|:---:|:---:|:-------:|:-------:|
| Linux   |  ✓  |  ✓  |  ✓  |    ✓    |    ✓    |
| Windows |  ✓  |  ✓  |     |    ✓    |         |

Linux binaries are fully static (musl). Windows binaries need only
`KERNEL32.dll` and the Universal C Runtime, both part of Windows 10/11.

## Checkout

The sources for DTC and libyaml are git submodules:

```sh
git clone --recurse-submodules https://github.com/technojo2000/DTC.git
# or, in an existing clone:
git submodule update --init
```

## Build

Requires Docker.

```sh
./build.sh          # build all targets into ./bin
./build.sh clean    # remove ./bin
```

Output lands in `bin/<os>-<arch>/`, along with:

- `SHA256SUMS`: checksums of every binary
- `RELEASE_NOTES.txt`: the submodule URLs, versions, commits, and whether
  each checkout was clean or dirty, so a build can be reproduced later

Set `ZIG_VERSION` to use a different Zig release (default `0.16.0`).

## Updating DTC or libyaml

```sh
git -C dtc fetch --tags && git -C dtc checkout v1.8.2
git add dtc
./build.sh
```

The same works for `libyaml`. No changes to the build scripts are needed.

## Layout

- `build.sh`: host entry point (build/clean, release notes)
- `docker/Dockerfile`: build image (Zig toolchain, flex, bison)
- `docker/build-all.sh`: runs inside the container; builds libyaml and DTC
  for each target
- `dtc/`, `libyaml/`: source submodules
